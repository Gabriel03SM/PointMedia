## ⚠️ OBSERVAÇÃO IMPORTANTE PARA O CODEX

Este projeto será desenvolvido do zero, utilizando a documentação oficial da Point Media e as páginas do Figma que serão disponibilizadas.

**Não tente implementar o sistema inteiro de uma única vez.**

Trabalhe de forma incremental, seguindo as fases estabelecidas, com prioridade para arquitetura, qualidade, segurança e funcionamento real.

**Regras obrigatórias:**

1. **Uma fase por vez:** desenvolva, teste e valide cada fase antes de avançar para a próxima. Ao concluir uma fase, apresente os resultados e aguarde minha autorização para continuar.

2. **Figma como referência visual:** as páginas serão fornecidas posteriormente. Não invente o design definitivo. Quando receber os arquivos, analise todas as telas e reproduza fielmente seus componentes, cores, dimensões e navegação.

3. **Documentação como referência funcional:** todos os requisitos presentes no PDF devem ser considerados. Não remova funcionalidades nem altere regras de negócio sem informar.

4. **Nada de funcionalidades falsas:** botões, formulários, tabelas, dashboards e operações devem funcionar de verdade, com integração real entre frontend, backend e banco de dados.

5. **Qualidade acima de velocidade:** evite código duplicado, soluções improvisadas, arquivos gigantes, dependências desnecessárias e arquiteturas difíceis de manter.

6. **Testes constantes:** execute os testes disponíveis após cada implementação. Não avance deixando erros conhecidos sem tratamento.

7. **Preserve a organização:** mantenha separação entre módulos, componentes, serviços, regras de negócio e acesso aos dados.

8. **Não tome decisões silenciosas:** quando a documentação ou o Figma não definirem algo, adote uma solução técnica justificável e registre a decisão. Questões críticas devem ser apresentadas para minha avaliação.

9. **Não altere ou apague arquivos existentes sem necessidade e autorização.**

10. **Mantenha o projeto executável:** cada fase concluída deve entregar funcionalidades verificáveis, e não apenas arquivos criados.

11. **INSTRUÇÃO ADICIONAL SOBRE O FRONTEND**

As páginas e componentes de frontend já existentes neste repositório representam o design oficial do sistema.

Antes de implementar qualquer funcionalidade, analise toda a estrutura visual existente.

**Não recrie, substitua ou redesenhe as páginas.** Preserve o layout, as cores, a tipografia, os espaçamentos, os componentes e a identidade visual.

Sua responsabilidade é integrar o design existente ao backend, implementar as funcionalidades reais e realizar apenas as adaptações técnicas necessárias.

Caso alguma alteração visual seja indispensável, explique o motivo e solicite autorização antes de executá-la.

Priorize a reutilização do código existente e não crie interfaces paralelas para funcionalidades que já possuem telas implementadas.
